router-agent · event bus design

多来源事件总线：一条事件的一生

把用户消息、运营群消息、GitHub Issue、Webhook、定时任务收成同一个信封，进同一个队列池；规则先判、Jev 兜底，按优先级出队，按时间窗口与 token 预算执行。

01

分层总览

七层单向依赖：采集 → 归一 → 排队 → 判定 → 调度 → 执行 → 观测。每层只做一件事，跨层只传信封，不传来源细节。

02

今天 vs 方案后

现状只有一条入站管道，且是同步串行处理的：消息进来就在下一个 tick 被处理，没有排队，也没有「先做哪个」。

维度今天（ra/tk-86-llm）方案后
入站来源只有飞书 长连接 lark-cli event consume5 类来源 飞书直发 / 运营群 / Issue / Webhook / 定时
接入方式仅 push 飞书推给我们push + pull + schedule 三种模式统一抽象
GitHub Issue没有监听 只有 PR 状态跟踪与「上报 issue」正式事件源 pull 轮询 + 游标 + 去重
Webhook不存在 全仓无接入面HTTP 端点 验签 + 防重放 + 限流
排队没有 同步串行事件队列池 优先级出队，P0 插队
判定规则 + 模型 规则只看准入规则定级 + Jev 兜底 明确的不调模型
成本控制无 全量即用窗口 + 预算 高峰只跑 P0/P1，超限延后
人工介入需求会话终审审核列表 队列级审核 + 卡片通知
关键约束用户消息的准入、开单、派工、回复语义全部保持不变，只在前面加一层队列；P0 走插队快路径，不能因为排队变慢。
03

优先级阶梯

来源决定基线，规则可以做小幅调整，模型只能在允许区间内动；P0 永远插队。

P0
用户直发 · 管理员

飞书里 @机器人 或私聊下需求。最高优先级，插队处理，不排在其它事件后面。

执行窗口：全天 · 审核：否
P1
运营群消息

群里一句话可能是在聊天而不是在下需求，默认进审核；命中明确规则时可升 P0。

执行窗口：全天 · 审核：是
P2
Issue / Webhook

主动收集来的事件。高峰只判定不执行，低峰批量执行；security 标签强制审核并立即通知。

执行窗口：低峰 · 审核：视规则
P3
定时任务 / 补跑

巡检、汇总、过期检查。纯规则决定，不调模型，只在低峰批量跑。

执行窗口：低峰 · 审核：否
04

规则先判，模型兜底

规则命中即定案，不进模型 —— 这是省钱和省时延的大头；只有灰区事件才交给 Jev。

Rule Engine · 确定性规则

免费 · 可解释 · 不调模型
  • 来源基线source-priority · 直接定级
  • 身份分流admin-actor 提权一级 · bot-actor 直接丢
  • 噪声门槛small-talk · noise-pattern 沿用现有规则集
  • 标签与风险security-label 强制审核 + 立即通知
  • 合并与限流duplicate-burst 合并 · rate-limit 超配额延后
  • 归属判定repo-bound 已有在办工单 → 转工单输入，不新开单

Jev 决策模型

按事件类型分级调用 · 失败降级不丢事件
  • P0 用户消息沿用现状：是否跟进 / 类型 / 紧迫度 / 项目相关性
  • P1 运营群小模型 + 短 prompt：是否是明确需求
  • P2 Issue / Webhook小模型 + 只读工具：是否需要人排查
  • P3 定时任务不调模型，规则完全决定 · 0 token
  • 硬边界模型只答「是否处理 / 类型 / 优先级区间 / 是否需人审」
  • 降级阶梯完整模型 → 小模型 → 纯规则 → 留在队列并标红
05

事件状态机

每个事件在队列里的位置都能查得到；延后不是丢弃，窗口开启自动继续。

pending 入队→ evaluating 判定→ review 审核→ dispatched 已派发/ deferred 延后/ failed 异常重试/ ignored 忽略归档
去重同一 dedupeKey 的重复投递不新增行，只更新计数与最后到达时间；Issue 被评论 5 次 → 一个工单，后续评论作为工单输入投递。
06

高峰只做重要的事，低峰批量做低优任务；token 到上限是延后，不是失败。

07

直派还是审核

审核只决定「要不要派」，派工仍走现有链路（Engine.decide() → Ticket → Mandate → 派工）。

条件动作说明
P0 用户直发 + 管理员发起直派保持现状体验
P0 用户直发 + 普通成员走 intake澄清后由管理员终审
P1 运营群消息审核群里一句话未必是需求
P2 Issue / Webhook + 规则明确直派限自动派发白名单项目
P2 + 模型判定有价值但不确定审核卡片推 admin
P2 + security / 数据风险 / 对外发布强制审核立即通知，不合并
P3 定时任务（只读巡检）直派只读工具范围
