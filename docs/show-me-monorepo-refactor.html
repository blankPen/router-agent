refactor · tk-68 · PR #82

从「一个大仓库」到可插拔的 monorepo

这次改造把 router-agent 拆成 pnpm workspace：领域内核、基础设施、Worker 运行时、消息通道各自成包， 宿主只做装配。对外仍然只发布一个 npm 包 router-agent，CLI 入口和 dist/ 结构对用户没有变化。

包 4（core / infra / runtime / channel） 依赖方向 单向向下 跨包别名 4 个，4 处解析一致 对外 npm 包 仍是 1 个 测试 1230 通过 / 4 跳过
01

目录：从混在一处到按职责分包

原来 src/core、src/infra、src/worker、src/channels 平铺在同一个 src/ 下， 谁都能 import 谁。现在内核与基础设施下沉成包，宿主 src/ 只保留装配（src/core/engine.ts 是宿主的 Engine / Store 层，留在 src/）。

before · 单包结构

  • src/
  • ├─ core/ model · stage · policy · events · engine
  • ├─ infra/ logger · process · chat · vision
  • ├─ worker/ port · registry · runtimes/ · orca/ · agents/
  • ├─ channels/ port · registry · router · ingress · feishu/
  • ├─ router/ · cli/ · web/ · store/
  • └─ config.ts 宿主唯一配置形状

after · pnpm workspace

  • packages/core/ ← src/core 的内核部分
  • packages/infra/ ← src/infra
  • packages/runtime/ ← src/worker
  • packages/channel/ ← src/channels
  • src/infra/ src/worker/ src/channels/
  • src/ router · cli · web · store · core/engine · config
注意不是「搬完就完」：搬完同时补了 packages/core/src/config.ts 的 RuntimeConfigView / ChannelConfigView，让适配器不再反向依赖宿主 AppConfig。
02

依赖方向：单向向下，越界有测试兜底

包之间只允许向下依赖；runtime 与 channel 互不依赖，packages/* 不得 import src/。

src/宿主 · Engine / Store / Router / API / CLI

装配层：把运行时注册进 RuntimeRegistry，把通道注册进 ChannelRegistry，负责配置与 CLI； 状态写入走 src/core/engine.ts，不直接碰数据库。

packages/runtime/WorkerRuntime 端口 + 适配器

定义 Worker 运行时端口与注册表，并实现各运行时适配器与 worker 手册模板。

packages/channel/ChannelAdapter 端口 + 适配器

定义消息通道端口与注册表，负责入站管线、飞书 adapter 与 lark-cli 封装。

packages/infra/基础设施

Logger、CommandRunner、对话模型、图片识别 —— 不含业务语义，零 Node 依赖方向问题。

packages/core/领域内核

Ticket / Mandate / Assignment / Stage / Policy / 事件与中立配置视图，零 Node 依赖。

守门tests/architecture/packages.test.ts 断言禁止的 import 组合，改边界时这个测试必须一起改。

「可插拔」落成两个端口接口：宿主只认端口，适配器在装配层注册；新增一种运行时或通道，不用改核心链路。

04

别名：四处解析必须一致

跨包引用统一走 #core/*、#infra/*、#runtime/*、#channel/*； 编译期、运行时、测试、面板打包各有一套解析，少改一处就会在某个环节炸。

别名指向解析位置（四处保持一致）
#core/*packages/core/src/* tsconfig.json paths · 根 package.json imports（指向 dist/）· vitest.config.ts alias · scripts/build-web.mjs 的 tsconfig
#infra/*packages/infra/src/*
#runtime/*packages/runtime/src/*
#channel/*packages/channel/src/*
坑根 imports 指向 dist/：改了 packages/*/src 必须 pnpm build， 否则 CLI 跑的还是旧产物；测试直接吃源码，所以测试绿了不等于运行时是新的。
05

构建与发布：用户视角零变化

npm 包仍然只有 router-agent 一个，files 仍只含 bin/ 与 dist/， dist/cli/main.js 的对外路径保持原样 —— 拍平这一步就是为了不破坏这个约定。

tsc -p tsconfig.build.json→ node scripts/build-web.mjs→ node scripts/flatten-dist.mjs→ dist/cli/main.js · dist/web · dist/update
发版scripts/release-plan.mjs 把 packages/<name>/src/** 视为产物改动（触发发版）， 包内 tests/、package.json、pnpm-workspace.yaml 不触发。
06

收益：新增一种运行时 / 通道的改动面

同样一件事，改动从「动核心 + 改 if/else 分支」变成「实现端口 + 注册一行」。

要做的事beforeafter
加一种 Worker 运行时改核心派工逻辑、加分支、加配置字段实现 WorkerRuntime + catalog 一行 + registry 装配
加一种消息通道改 Router 与宿主配置实现 ChannelAdapter + 注册进 ChannelRegistry
适配器要读配置import 宿主 AppConfig（反向依赖）用 packages/core/src/config.ts 的中立视图
越界 import靠自觉，review 才拦得住架构测试直接红
