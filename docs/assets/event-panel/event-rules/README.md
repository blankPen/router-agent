# 事件决策规则 · Web 面板界面 Before / After

同一视口（1440×900 @1x）、同一主题（浅色）、同一份配置（`events.rules` 为空）。

| 截图 | 说明 |
|-|-|
| `config-rules-before.png` | 改造前：配置页的「事件总线」只有来源与一段全局判定 prompt，没有按事件类型区分的规则入口 |
| `config-rules-after.png` | 改造后：新增「决策规则」分组——按 `eventType` 精确匹配，每条规则自带判定问题、执行流程与护栏；下面保留「判定方式与全局兜底」 |
| `events-before.png` | 改造前：事件页只有待审核 / 待处理 / 已完成 / 无效四类状态，没有「未判定」这一档 |
| `events-after.png` | 改造后：概览新增「未判定」计数与状态筛选；没有匹配规则的事件只收集、不判定、不派工 |

界面改动说明：

- 规则区是独立分组，不挤在来源卡片下面；空状态直接说明「新装默认不判定」。
- 「判定方式与全局兜底」把 provider（部署级选择）、旧版全局 prompt、兜底开关拆开，旧的 prompt 标注为兼容保留。
- 事件页的统计与筛选都补上了「未判定」，这一档的事件不占人工、不计配额。
