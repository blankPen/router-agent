# 事件决策规则 · Web 面板界面 Before / After

同一视口（1440×900 @1x）、同一主题（浅色）、同一份配置（`events.rules` 为空）。

| 截图 | 说明 |
|-|-|
| `config-rules-before.png` | 改造前：配置页的「事件总线」只有来源与一段全局判定 prompt，没有按事件类型区分的规则入口 |
| `config-rules-after.png` | 改造后：新增「决策规则」分组——按 `eventType` 精确匹配，每条规则自带判定问题、执行流程与护栏；下面保留「判定方式与兜底」 |

界面改动说明：

- 规则区是独立分组，不挤在来源卡片下面；空状态直接说明「新装默认不判定」。
- 「判定方式与兜底」只放 provider（部署级选择）、置信度阈值与兜底策略；判定依据统一在规则里，没有全局 prompt。
- 事件页的统计与筛选都补上了「未判定」，这一档的事件不占人工、不计配额。

## 六、添加决策规则弹窗：样式重做

同一视口（1440×900 @1x）、同一份配置（`events.rules` 为空）、同一 UI 状态（刚点开「添加规则」）。明暗主题各一组。

| 截图 | 说明 |
|-|-|
| `rule-modal-before.png` | 改造前（浅色）：十几个字段平铺成一条长表单，没有分组、没有层级，`auto` / `review` / 三个阈值各自占整行，标签与控件全是 12px 灰字，看不出哪些字段相关 |
| `rule-modal-after.png` | 改造后（浅色）：按「规则范围 → 你的意图 → 四个判定问题 → 执行流程 → 阈值与护栏」五段分组，段落间用 1px 细线分隔，标题带步骤序号；`auto` / `review` 与三个阈值改为并排栅格 |
| `rule-modal-before-dark.png` | 改造前（深色）：同一场景的深色基线 |
| `rule-modal-after-dark.png` | 改造后（深色）：深色主题下层级同样成立 |
| `rule-modal-after-error.png` | 改造后：保存校验失败时，错误在弹窗底部就地显示，不再被遮罩挡住 |

界面改动说明：

- 表单拆成五段，每段有标题与一句说明，字段不再是一串平铺的长列表；段落之间只留 1px 细线，不套卡片。
- 标题层级拉开：弹窗标题 16px / 分段标题 14px / 字段标签 12.5px / 字段键名 11px 等宽灰字。
- `auto` 与 `review` 两个闭集并排，优先级判定改成「判定说明 + 档位」两块带小标题，避免两个文本框糊在一起。
- 三个阈值并排成一行栅格，数字等宽对齐，横向比较更省事。
- 文本框统一行高、内边距与 hover / focus 态，focus 用项目既有的 accent 焦点环。
- 新建与编辑的标题分开（`添加决策规则` / `编辑决策规则`），保存校验失败时错误就地显示在弹窗底部。
- 字段集合、提交逻辑、校验规则与后端接口契约均未改动。
