# 事件总线 · Web 面板界面 Before / After

同一视口（1440×1000 @1x）、同一主题（深色）、同一份配置与同一份队列数据（本地真实运行的服务：`node dist/cli/main.js start --foreground --no-open`，配置为占位值，未包含真实密钥、群 id 或用户数据）。

## 一、事件页：从「配置 + 查看混在一起」到「只查看与审核」

| 截图 | 说明 |
|-|-|
| `before.png` | 事件功能上线前：面板顶部没有「事件」入口，事件只能靠飞书消息进入系统 |
| `before-events-config.png` | 事件页初版：事件来源卡片与决策 prompt 编辑器都堆在事件页里，与队列表格混排 |
| `after.png` | 改造后的事件页：来源与判定 prompt 全部移走，只留队列概览、优先级/状态筛选与人工审核动作；待审核的行左侧有琥珀色标记，一眼能扫到要处理哪几条 |

## 二、配置页：事件配置回到「配置」里

| 截图 | 说明 |
|-|-|
| `config-before.png` | 改造前：配置页没有事件相关分组，事件配置只能在事件页里改 |
| `config-after.png` | 改造后：配置页新增「事件总线」分组——总开关、事件来源、决策策略（判定方式 / prompt / 置信度阈值 / 兜底）、成本与时间窗 |
| `config-after-source.png` | 事件来源展开的样子：每个来源一行，展开后按来源自己声明的字段渲染（仓库、轮询间隔、标签白名单、默认优先级……），跟其它配置项一样由底部保存条统一落盘 |
| `config-after-saved.png` | 改完来源字段后的保存条：显示「1 项未保存」，点「保存配置」后提示「已保存 1 项，已立即生效」，config.yaml 同步更新 |

界面改动说明：

- 事件页概览改成「一块容器 + 细线分栏」，不再是一排四张统计卡；颜色只用在数据上（优先级圆点、待审核的琥珀色状态与行标记）。
- 表格改用规则与对齐，不做斑马纹、不做卡片套卡片；操作按钮一行排开，不再竖着叠成一列。
- 决策 prompt 从「一整块大文本框」变成配置页里的多行字段，与判定方式、阈值并排成一组。
- 所有样式复用面板既有 token（`--surface` / `--rule` / `--accent` / `--warning` 等），没有另起一套样式体系，明暗主题共用同一份规则。
