多来源事件总线 · 整体流转

所有来源先归一化成统一事件进事件队列池，由规则层 + Jev 决策模型判定「要不要处理、什么类型、多急、要不要人介入」，再分级派发；全程受成本闸门与可配置时间窗约束，事件状态对用户在面板可见。来源只给基线，不定处理方式。

来源 用户消息 / 运营群 / Issue / Webhook / 定时任务 幂等键 (source, externalId) 判定 所有来源同一套 直派与否 看判定与置信度 时间窗 / 预算 可配置 · 预算默认不限 派发 T0 直派 / T1 审核 / T2 归档 / T3 丢弃 参考 agent-autoloop 的语义

02优先级判定：规则层 + Jev 双层

规则结论
scope:admins / mention / all群范围第一道闸：不在群里算数就不进队列
identity:admin提高基线优先级，允许直派（默认管理员 + 群级扩充）
keyword:sev0 / sev1提高基线优先级（线上告警 / 疑似 Bug）
project:unbound前置不满足 → T1 审核
scope:undecidable判定不出授权范围 → T1 审核
budget:exhausted延后到下一个窗口（预算默认不限）
window:closed延后到窗口开始
dedupe / noise / botT3 丢弃（留一行记录）
Jev · event.triage.v1档位
needsHandling 是否需要处理noul · 阈值 0.6
eventType 类型告警 / 缺陷 / 需求 / 信息 / 噪音
priority 优先级立即 / 高 / 中 / 低
needsHuman 是否需人介入noul · 阈值 0.5
projectRelated 与项目相关noul · 无关则归档

融合：规则置信度 × 模型置信度取低值；置信度 < 0.5 一律 T1 进审核；规则已判终局的不被模型改写； 模型失败 → 用规则结论继续并标 degraded，绝不静默丢弃。
来源只给基线（用户消息 100 / Issue 70 / webhook 50 / 定时 40），不出现在 tier 判定里。

03分级派发

T0 · 直派

直接开单派工

判定「需要处理」且置信度达标、不需人介入、前置条件满足。任何来源都可能是 T0。

cond: 判定结论 + 置信度 + 四条前置条件
T1 · 审核

进审核队列

判定要人介入、置信度不足、项目未绑定或授权范围不可落地。飞书卡片 + 面板待审列表。

cond: 需人拍板
T2 · 归档

只留痕可检索

与项目无关、纯通知类、可在面板搜索追溯；可配日报汇总，不打扰。

cond: 不处理但值得留痕
T3 · 丢弃

丢弃但记一笔

机器人自发、寒暄、幂等重复。写日志便于事后追溯为什么没处理。

cond: 无处理价值

04成本控制与可配置时间窗

时间窗先留空（默认一直放行）；下面的窗口划分只是示例，不预置，需要时在配置里启用。

示例 · window: night 00:00–06:00

低峰 · 全量 + 批量

放行 T0~T3；同 source + type + project 的事件合并成一次 Jev 调用，调用次数 N → 1；合并失败自动退回逐条判定。窗口可在面板改。

示例 · window: peak 09:00–20:00

高峰 · 只放要紧事

只放行 T0 / T1；低优事件排队或延后，模型调用优先保响应。

示例 · window: offpeak 20:00–09:00

平峰 · 常规节奏

放行 T0 / T1 / T2；T3 归档不派发。

配置项 · budget daily

预算闸门（默认不限）

可配置日 token / 日事件数；默认 0 = 不限制，配了才拦截；触顶后先不调模型、低优事件延后到次日，已判定完的 T0 仍执行，并记 event:budget-exceeded。

时间窗闸门event.windows[].allow
预算闸门dailyTokens / dailyEvents
并发与背压闸门maxWorkers / maxQueueDepth

降级链：规则命中 → 直接定案（0 模型调用）；规则无法定论 → Jev；Jev 超时 / 非法 / 超预算 → 规则结论 + degraded 标记并优先转 T1 审核。

06落地顺序

阶段内容验收
P0 事件底座事件契约 + 队列表 + 规则层判定 + 面板只读列表 + GitHub Issue 轮询Issue 作为第一个非飞书来源进队列；用户消息插队零退化
P1 判定与派发Jev event.triage.v1 + 护栏 + T1 审核队列 + 统一待审核（合并需求终审）+ 飞书通知判定与来源解耦：同一套规则出 T0/T1
P2 成本与主动性可配置时间窗 + 可配置预算（默认不限）+ 批量合并 + later 定时复查 + Issue webhook 验签夜间自动批量跑低优；轮询可平滑切 webhook
P3 自产事件hops 熔断 → 规则白名单 → worker --emitA→B→A 自激被熔断；越权 emit 被拒

顺序不可错：熔断必须先于自产事件（否则自激无法归因）；时间窗必须先于批量（否则批量会在高峰期偷偷跑）。
