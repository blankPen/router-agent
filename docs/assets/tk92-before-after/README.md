## 1. 配置 → 事件总线：来源卡 + 决策规则 → 只读事件目录卡

| 截图 | 说明 |
|-|-|
| `before-config-event-bus.png` | 改造前：「事件来源」段只有 GitHub / feishu 两张**开关卡**（点「设置」才进弹窗逐仓库勾事件类型）；下面是独立的「决策规则」段，带「添加规则」按钮，规则不存在时提示「还没有决策规则」 |
| `after-config-event-catalog.png` | 改造后：「事件源目录」段是**只读目录卡** —— 逐条列出可订阅的事件类型（`github.issues.opened` / `feishu.message` …）、人话标签、可用性标注（「开箱可用」/「需后台订阅」）与订阅计数（「尚未订阅」/「被 1 个任务订阅」）。**决策规则整段删除**，页面上没有任何事件类型多选控件 |

变化要点：来源不再持有订阅，「勾选事件类型 → 再写一条规则」的两步操作被彻底去掉；
用户看到的是「有什么可订阅」，订阅关系改由自动化任务承载。

## 2. 自动化：填表弹窗 → 会话面板

| 截图 | 说明 |
|-|-|
| `before-automation-new-modal.png` | 改造前：「新建自动化」是分段填表弹窗（基本信息 → 类型与内容 → 执行环境 → 触发计划），字段全靠用户自己填，填错只在校验时才知道 |
| `after-automation-conversation.png` | 改造后：唯一入口是「用一句话新建」，展开**会话面板** —— 助手消息流 + 底部输入框 + 右侧会话清单。参数齐了才出预览卡（触发方式 / 连接参数 / 过滤条件 / 处理方式 / 归属项目 / 运行时），确认后才落库 |

变化要点：操作成本从「填 8 个字段」变成「说一句话」；缺什么助手只追问那一项；
目录里没有的事件类型被明确拒掉并列出目录实际内容。

## 3. 自动化任务列表

| 截图 | 说明 |
|-|-|
| `before-automation-tasks.png` | 改造前：任务只有定时触发（`AI 自动化 · 每周一 09:00 · router-agent`），操作是「编辑 / 执行一次 / 停用 / 删除」 |
| `after-automation-tasks.png` | 改造后：任务卡同时承载「订阅什么 + 命中后做什么」——处理方式标签（自动执行 / 待人审）、订阅的事件类型、过滤条件（关键词 + 语义）、触发方式说明；操作换成「恢复会话 / 执行一次 / 停用 / 删除」 |

变化要点：任务即订阅。停用任务订阅随之消失；删除任务订阅一并消失。
「恢复会话」回到绑定的原会话，历史完整，可继续迭代改同一条任务。
