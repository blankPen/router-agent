# 自动化页布局重构 · Before / After

同一场景（Web 面板「自动化」页）、同一视口（1440×900 @2x）、同一主题（浅色）。

- **基线（Before）**：`5ca6de8`（tk-92 八阶段实现已推送）
- **改动版本（After）**：`ra/tk-92-输出事件订阅与自动化任务重构方案文档` 工作分支

截图取自本地真实运行的服务（`node dist/cli/main.js start --foreground`，临时 `RA_HOME`），
配置内容是占位值，未包含任何真实密钥。

## 1. 任务卡网格 + 折叠会话面板 → 左侧任务栏 + 右侧大 Chat 会话

| 截图 | 说明 |
|-|-|
| `before-automation-layout.png` | 改造前：主区是**任务卡网格**（每张卡摊开描述、订阅类型、过滤条件、提示词、下次触发、5 个操作按钮），会话面板要点「用一句话新建」才展开，展开后是「消息流 + 底部输入框 + 右侧会话清单」的三块布局 |
| `after-automation-layout.png` | 改造后：**左侧竖排任务栏**（一行标题 + 一行「处理方式 · 触发摘要」，操作按钮 hover 才显形），**右侧主区就是一个大 Chat 会话窗口** —— 对话内容在上，**输入框浮在底部**。截图里点了「CI 失败自动修复」卡片，会话已切到那条任务的原会话并恢复历史 |

变化要点：页面从「看一堆任务卡」变成「在一个会话里干活」；任务卡从信息展示降级为**会话入口**，
点一下就切到那条任务绑定的会话接着聊。任务卡本身也精简了 —— 只剩标题、状态点和一行触发摘要。
